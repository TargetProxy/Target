# Smart Connect 需求说明

## 1. 目标

Smart Connect 将多个订阅、多个机场的节点统一管理，并根据目标服务自动选择符合地区要求且质量最优的节点。

```
多个订阅 → 统一节点池 → 服务策略 → 候选筛选 → 质量评估
        → 服务绑定 → 多 Selector / 域名路由 → TargetLib 执行
```

## 2. 设计原则

- **服务级选择**：不同服务可以使用不同机场、不同地区。
- **显式策略**：自动选择必须遵循可查看、可编辑的策略。
- **无隐式 fallback**：节点或订阅失败后不得静默切换。
- **粘性绑定**：同一服务在绑定有效期内尽量使用同一节点。
- **可解释**：必须展示选择结果、评分和排除原因。
- **实际结果优先**：地区和服务能力以探测结果为准。

## 3. 范围

### 3.1 本期包含

- 多订阅和多机场管理；
- 统一节点池；
- 服务策略配置；
- 按地区、订阅、标签筛选候选节点；
- 服务级可用性探测；
- 节点质量评分；
- 服务到节点的绑定；
- 绑定到运行时路由规则；
- 失败原因和评估记录展示。

### 3.2 明确不包含

- 节点失败后的自动故障转移；
- 订阅更新失败后的自动换订阅；
- 后台无提示的多节点重试；
- 仅按最低延迟选择节点。

## 6. 关键业务流程

### 6.1 构建统一节点池

```
读取已启用订阅
    ↓
解析节点并生成稳定 Node ID
    ↓
合并节点和历史质量数据
    ↓
写入统一节点池
```

### 6.2 自动选择

```
匹配目标域名
    ↓
读取服务策略
    ↓
是否存在有效绑定？
 ├─ 是 → 使用当前绑定
 └─ 否 → 构建候选节点
              ↓
        过滤禁用、排除节点
              ↓
        过滤不符合地区节点
              ↓
        执行服务可用性探测
              ↓
        排除探测失败节点
              ↓
        计算综合评分
              ↓
        创建服务绑定并应用路由
```

### 6.3 失败处理

```
节点探测失败
    ↓
记录失败原因
    ↓
当前评估失败
    ↓
不自动切换节点
    ↓
展示“重新评估 / 手动选择 / 查看日志”
```

## 7. 功能需求

### FR-001 多订阅

- 支持同时保存多个订阅。
- 每个订阅支持启用、禁用、更新、删除和优先级设置。
- 禁用订阅不得进入候选集。
- 更新失败不得自动切换其他订阅。
- 更新失败时保留原运行配置，并展示错误原因。

### FR-002 统一节点池

- 展示所有已启用订阅中的节点。
- 显示节点来源订阅、机场、地区、协议和质量。
- 支持节点收藏、排除、启用和禁用。
- 节点名称变化不应导致历史质量数据完全丢失。

### FR-003 服务策略

- 支持预置服务策略和自定义服务。
- 支持自定义域名、允许地区、首选地区。
- 支持限定订阅和排除节点。
- 支持将 Direct 作为明确的策略结果。
- 修改策略后，相关绑定必须标记为待重新评估。

### FR-004 节点评估

- 支持延迟测试和服务目标可用性探测。
- 记录测试时间、成功率、失败原因和出口地区。
- 区分 DNS、TCP、TLS、HTTP、认证和超时错误。
- 支持取消批量评估。

### FR-005 节点选择

- 不符合地区要求的节点直接排除。
- 服务探测失败的节点直接排除。
- 选择不能只依赖延迟排序。
- 保存评分和选择原因。
- 无可用候选节点时展示明确失败状态，不自动换策略。

### FR-006 服务绑定

- 每个服务策略可以绑定一个实际节点。
- 绑定记录节点、时间、有效期、状态、评分和原因。
- 绑定有效期内不得因单次延迟变化自动切换。
- 只有用户主动重新评估或明确触发重新选择时才允许更换。

### FR-007 运行时路由

- 不同服务必须可以绑定不同 outbound。
- 支持域名到 selector 或 outbound 的映射。
- UI 必须显示 TargetLib 实际生效的绑定。
- TargetLib 能力不足时必须明确提示，不得展示虚假成功状态。

### FR-008 可解释性

用户必须能查看：

- 当前服务使用的节点和所属订阅；
- 实际出口地区；
- 节点评分和最近测试时间；
- 选择该节点的原因；
- 其他节点被排除的原因；
- 当前绑定的运行时状态。

## 8. 评分与选择规则

```
地区符合性      不符合则排除
服务可用性      不可用则排除
稳定性          成功率、丢包率
实际出口地区    以探测结果为准
延迟            用于排序和打破平局
用户偏好        收藏、标签、订阅优先级
```

评分优先级：

```
服务可用性 > 实际出口地区 > 稳定性 > 丢包率 > 延迟 > 用户偏好
```

## 9. 无 fallback 约束

### 禁止

- 当前节点失败后后台静默切换；
- 当前订阅更新失败后自动使用其他订阅；
- 服务不可用时自动尝试多个节点；
- 用过期测速结果伪装成当前可用状态；
- 未经用户确认改变服务出口地区；
- 失败后无限重试并持续建立新连接。

### 允许

- 首次绑定前评估候选节点；
- 用户主动点击“重新评估”；
- 用户主动手动选择节点；
- 用户修改策略后重新生成绑定。

失败状态示例：

```
ChatGPT
当前节点：Singapore-03
状态：不可用
原因：TLS handshake timeout

[重新评估] [手动选择] [查看日志]
```

## 10. TargetLib 能力要求

目标配置：

```
多个订阅 → 多个节点池 → 多个服务 Selector
                         ↓
                 域名到 Selector 路由
```

示例：

```
chatgpt.com    → selector.chatgpt → Singapore-03
disneyplus.com → selector.disney  → US-West-02
youtube.com    → selector.youtube → Japan-01
国内网站        → direct
```

如果 TargetLib 仍只有单一 `proxy` selector，则只能实现“全局自动选择一个节点”，不满足本需求的服务级 Smart Connect。

## 11. 界面需求

### 11.1 总览页

```
服务       当前节点          来源订阅     状态
ChatGPT    Singapore-03      A机场        可用
Disney+    US-West-02        B机场        可用
YouTube    Japan-01          C机场        可用
```

### 11.2 服务详情页

必须展示：

- 允许地区和首选地区；
- 当前节点；
- 延迟、稳定性和实际出口地区；
- 最近评估时间；
- 选择原因；
- 重新评估和手动选择入口；
- 查看日志入口。

## 12. 非功能需求

- 评估过程不得阻塞普通 UI 操作。
- 评估和选择必须可取消。
- 订阅更新、节点测试和运行时切换必须有明确状态。
- 应用重启后恢复服务策略和绑定。
- 所有自动选择必须写入结构化日志。
- 日志不得泄露订阅 Token、认证信息和敏感 URL。
- Smart Connect 不得绕过用户配置的节点排除和地区限制。

## 13. 分阶段交付

### Phase 1：数据基础

- 多订阅统一管理；
- 统一节点池；
- 稳定节点 ID；
- 收藏、排除和启用状态；
- 服务策略持久化。

### Phase 2：自动评估

- 地区过滤；
- 服务探测；
- 质量记录；
- 评分和选择原因；
- 手动重新评估。

### Phase 3：运行时接入

- 多 selector；
- 域名到 selector 的路由；
- 服务绑定同步；
- TargetLib 实际状态回传。

### Phase 4：完善体验

- 测速历史；
- 实际出口地区检测；
- 区域解锁检测；
- 绑定有效期；
- 诊断包导出；
- 策略模板和自定义服务。

## 14. 验收标准

- 可以同时添加并启用多个订阅。
- 统一节点池可以显示节点来源。
- 可以为 ChatGPT、Disney+ 等服务配置不同地区策略。
- 不同服务可以生成不同节点绑定。
- 不同服务的流量可以进入不同 outbound。
- 可以查看评分、选择原因和排除原因。
- 节点失败时不会静默切换。
- 订阅更新失败时不会自动切换订阅。
- 无可用节点时展示明确失败状态和操作入口。
- 应用重启后可以恢复策略和绑定。
- TargetLib 能力不足时明确显示未支持状态。
